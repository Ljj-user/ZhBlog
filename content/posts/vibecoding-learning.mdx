# 想法记录

需求定义
→ 信息架构
→ 模块拆分
→ 数据流
→ MVP
→ AI批量实现
→ 最后统一优化

文档驱动开发：
项目前期指挥ai工作一定要思考清楚：这个功能是核心功能？还是为了更好看更高级？

### 正确姿势1：
先写文档PRD，再让AI干活

```
PRD.md
目标：做一个AI交易复盘工具
核心功能：
1. 上传交易记录
2. 自动分析盈亏
3. AI总结错误
4. 生成周报
不做：
- 社交
- 动画
- 多主题
- 实时同步
```
  structure.md、api.md

### 正确姿势2
不要让AI自由发挥
	prompt:
```
只修改 xxx 文件
不要动其它逻辑

保持当前架构
仅增加：
1.
2.
3.
```
### 正确姿势3
先做MVP，而不是完整产品，先做最重要的功能。

错误：
 做完整量化平台
正确：
 先做：
 上传CSV → AI分析 → 输出建议

- dashboard
- 自动回测
- 多账户
- 信号系统
这些以后再做。

### 正确姿势4
掌握真正的开发节奏：
目标1：能跑
目标2：用户能跑通
目标3：不报错
目标4：体验优化（UI、动效、智能化、微交互）

### 正确姿势5：
明确本次要开发什么，明确不做什么。
